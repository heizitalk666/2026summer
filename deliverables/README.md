# deliverables/ —— 每人一个文件夹

规则见 [`docs/交付物清单.md`](../docs/交付物清单.md)。一句话：
**交代码、交权重、交「我训完了」都不算交付**，每人交同样三样——
一张图、一张数字表、一句话结论，外加产物本身供复现。

| 目录 | 负责人 | 状态 |
|---|---|---|
| [`甲-检测/`](甲-检测/) | 甲 · L1 检测 | ⚪ 空模板已建，未开工 |
| [`乙-分割/`](乙-分割/) | 乙 · L2 分割 | 🟡 已汇报数字，**待补齐**（见其 `补齐清单.md`） |
| [`丙-异常/`](丙-异常/) | 丙 · L3 异常 | ⚪ 空模板已建，未开工 |

每个目录里除了 `README.md`（一页纸，进 PPT）之外，还有一份
`避坑清单.md` / `补齐清单.md`——**那是工作用的，不进 PPT**。
里面是组长核对代码时记下的坑，每条都指到了行号，开工前先扫一遍。

三个人的分工与验收标准见 [`docs/后续计划与分工.md`](../docs/后续计划与分工.md)：
甲 `:169`、乙 `:201`、丙 `:241`。

**交不出来的如实写「未做 / 未验证」，不要交一个凑出来的数。**
这个项目的习惯是 README 里挂着「重复性压线超差」——保持住。

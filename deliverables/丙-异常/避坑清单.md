## 1. 基线已经满分了，这是你最大的问题（先读这条）

`patrol/perception/anomaly.py:84` 的 `StatisticalAnomaly` docstring 记着实测：

> 样本到 30 个以上后正常最大 1.5σ、异常 ≥6σ，
> **72 个正常 / 12 个异常样本上误报漏报皆为 0**

**一个零权重、当场能跑、还可解释的方法，在现有样本上已经满分。**
如果你在同一批样本上比 EfficientAD，最好的结果也只是打平——
这张比选表就没有信息量。

这和乙那边踩的是同一个坑的另一种样子：**测试集分不开两个方法时，
比选结论是被测试集预先决定的，不是被方法决定的。**

**建议的做法**，二选一或都做：

1. **把样本做难。** 现有异常样本是 6σ 级别的显著异常。加一批**弱异常**
   （轻微变色、小面积渗漏、部分遮挡），让统计法开始出错，差距才显得出来。
   `gen_synthetic` 的合成路径可以控制异常强度。
2. **换个更有区分度的指标。** 误报/漏报在满分处饱和，改报
   **AUC** 或**正常与异常分布的间隔（以 σ 计）**——统计法是 1.5σ vs 6σ，
   EfficientAD 能拉到多少？这个数不会饱和，也更好画成 `score_dist.png`。

第 2 条工作量小，**建议至少做它**。

## 2. warmup 不能小于 30，否则你会测出一个假的漏报

同一段 docstring 记着一次实测踩坑：

> 样本只有 24 个时，正常分布的 σ 估得偏大，异常目标只能拿到 2.8σ，
> 落在 3.3σ 阈值以下**漏报**

也就是说**样本给少了，统计法会假装很差**。如果你拿一个 warmup 不足的
统计法当基线去比，赢了也是假赢。跑对比前先确认正常样本数 ≥ 30，
最好远大于 30。

## 4. `l3_report.json` 有个小坑：脚本是**打印**不是落盘

`training/train_anomaly.py:179-180` 是两条 `print`：

```python
print(json.dumps(info, ensure_ascii=False, indent=1))
print("\n把它接进去：configs/system.yaml → perception.l3.weights: %s" % info["out"])
```

**直接 `> artifacts/l3_report.json` 会得到一个非法 JSON**——JSON 后面跟着
一句中文。正确做法：

```bash
python -m training.train_anomaly ... | head -n -2 > artifacts/l3_report.json
# 或者干脆跑完手动把 JSON 那段粘进文件，确认能被 json.load 读回来
python -c "import json;json.load(open('artifacts/l3_report.json'));print('JSON 合法')"
```

## 5. 非监督的立论要讲出来，这是你这一路最值钱的地方

`docs/后续计划与分工.md:267` 的原话：

> 非监督，**只用「看起来正常」的样本**。这正好绕开任务书提到的数据可得性约束
> ——室内配电室的渗漏油、呼吸器变色几乎没有公开标注数据，
> 但「正常设备的图」要多少有多少，巡检跑一轮就攒下一批。

甲那一路卡在「要下 2773 张带标注的公开数据」，你这一路**根本不需要标注**。
这个对比本身就是答辩材料——它解释了为什么四类模型要分开做，
而不是训一个更大的 YOLO。

顺带：这也是为什么 `--from-evidence` 那条路比合成正常集更好——
用系统自己跑出来的证据包当正常样本，分布最接近真实。

## 6. 可解释性是统计法的加分项，别忘了在表里给它

`patrol/perception/anomaly.py:19`：

> 可解释——异常分来自哪个特征通道是能说清楚的，答辩时比一个黑盒分数好讲。

比选表里「可解释」那一列不是凑数的。如果 EfficientAD 只是打平，
**统计法凭「零权重 + 可解释 + 当场能跑」就应该继续当默认**，
这个结论完全站得住，写出来即可。

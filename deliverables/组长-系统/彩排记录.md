### 端口没清干净会怎样（本次实测）

彩排时连着两轮拿到这样的输出：

```
!! cloud 退出，返回码 3
!! perception 退出，返回码 1
```

而小结照常打印，只是复核成功率掉到 40–50 %、密度比掉到 0.65–1.08（正常 1.8–2.4）。
**最坑的地方在于它不像坏了**——小结有模有样，不盯着那两行 `!!` 就会把这组数当成
真实测量抄进报告。原因是上一轮的进程没退干净，占着 8000 与 `bus.*`；
新起的 cloud 与 perception 直接退出，系统在缺两个进程的情况下继续跑完了 300 秒。

**演示前固定动作**（不是「必要时」）：

```bash
pkill -9 -f 'tools.run_all|cloud.server|patrol.(gateway|mission|perception|uploader).node'
sleep 4
ss -ltn | grep 8000 || echo "8000 空闲"
```

清干净之后同样的命令一次就正常：45 s 短跑产出 3 个证据包、复核成功率 100 %、
密度比 1.89–2.19，`!!` 一行没有。

> **`演示指南` §5 里写的还是「51 项」「496 条用例」，本次已一并改正。**
> 数字对不上是彩排最常抓到的一类问题——它不影响演示，但答辩现场被问到
> 「你说 51 项，屏幕上是 57」会很难解释。

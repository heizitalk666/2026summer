# 代码地图与整体架构

> 网页版（图更清楚）：https://claude.ai/code/artifact/a60883c3-1af2-4ac3-b934-71c32c3be5f6
> 配套：[后续计划与分工](后续计划与分工.md)

给组里其他人的一份"这个文件是干嘛的"清单。架构的**设计理由**在
`docs/架构说明.md` 与 `docs/设计思想.md`，这里只回答两个问题：
**东西放在哪、为什么放在那。**

规模：Python 约 21 300 行，其中测试 5 900 行（507 条用例）；文档 4 700 行；
配置 520 行；5 份 JSON Schema。

---

## 一、一句话

四个进程，跑在一台机器上，用 ZeroMQ 说话；只有一个进程能碰执行器，
只有一个进程能碰模型；它们之间说的话由 5 份 JSON Schema 冻结。

```
  perception ──IF-1 DetectionEvent──▶ mission ──IF-2 ControlCommand──▶ gateway
      ▲                                  ▲            ◀──CommandAck──      │
      └──────────IF-3 StatusReport───────┴─────────────────────────────────┘
                          │
                       uploader ──IF-4 EvidencePackage──▶ cloud
```

**为什么非要拆成四个进程**（这是最常被问的）：安全网关必须是唯一能碰执行器
的地方，而且必须能在 AI 进程崩掉之后继续工作。同一个进程里做不到——
一个段错误会把两边一起带走。`README.md` 里那条"杀掉 AI 进程后车自己走完
路线"的演示，验的就是这条边界。

---

## 二、四个进程的分工

| 进程 | 入口 | 拥有什么 | 绝不碰什么 |
|---|---|---|---|
| **gateway** 安全网关 | `patrol/gateway/node.py` | 四个驱动实例（唯一） | 模型、图像 |
| **perception** 感知 | `patrol/perception/node.py` | 相机、四路模型 | 执行器（驱动以 `passive=True` 建，收不到指令） |
| **mission** 任务 | `patrol/mission/node.py` | 十状态机、PID 伺服、预算 | 驱动、模型 |
| **uploader** 上传 | `patrol/uploader/node.py` | 证据目录、上传队列 | 驱动、模型 |

一键起全部：`python -m patrol.tools.run_all --seconds 300`

## 三、一次复核的完整数据流

这条线走通了，整个系统就是通的。**读代码建议顺着它读一遍。**

| # | 谁 | 干什么 | 代码位置 |
|---|---|---|---|
| 1 | perception | 30 Hz 巡航，L1 检测出一块表，置信度落在 0.25–0.60 带内 | `perception/node.py::process_frame` |
| 2 | perception | 铸 `event_id`（**只在车在动、变焦在广角端时铸**），发 IF-1 `is_suspect=true` | 同上，`new_uuid()` 那一段 |
| 3 | mission | 连续三帧同一 `track_id` 才确认，查三条抑制规则与预算 | `mission/fsm.py::_st_cruise`、`suppress.py`、`budget.py` |
| 4 | mission | 下 `PAUSE` → 网关校验五项 → 底盘停 | `mission/fsm.py::_st_halt_req` → `gateway/checks.py` |
| 5 | mission | 前馈粗对准（针孔几何算 `aim_offset`）+ PID 残差闭环把目标居中 | `mission/fsm.py::_st_aim`、`mission/servo.py` |
| 6 | mission | 按 `zoom_for_density(1.0, p_before, 120, 3.0)` 算倍率并下发 | `scene/optics.py::zoom_for_density` |
| 7 | perception | 从 IF-3 认出"状态机在等复核报文"，跑四路模型 + 融合 | `perception/node.py::verify_due` → `fusion.py` |
| 8 | perception | 融合结论写 `evidence/<run>/<event>/fusion.json` | `perception/node.py::_dump_fusion` |
| 9 | mission | 状态机过程写 `mission_ctx.json` | `mission/node.py::_dump_ctx` |
| 10 | uploader | 配对 before/after，合并两个 sidecar，出 `manifest.json` | `uploader/node.py::_finish`、`packer.py` |
| 11 | uploader | 先传元数据再传文件，断点续传 | `uploader/transport.py` |
| 12 | cloud | 入库、台账、人工裁决 | `cloud/db.py`、`cloud/server.py` |

**第 8、9 步为什么走文件而不走总线**：IF-1 的 Schema 是
`additionalProperties: false`，OCR 原文和状态机内部过程塞不进去；而 ICD §6.1
本来就把"证据目录的结构"定义成契约。两个进程读写同一个
`<run_id>/<event_id>/` 目录属于这个契约内的用法，不必新开第五条接口。

## 四、代码地图

### `patrol/common/` —— 所有进程共用的地基（869 行）

| 文件 | 行 | 干什么 | 为什么存在 |
|---|---|---|---|
| `messages.py` | 310 | 四条接口的报文构造与校验 | **报文只能从这里造。**手拼 dict 迟早漏字段，而 Schema 违规要到对面才炸 |
| `bus.py` | 197 | ZeroMQ 封装：Publisher / Subscriber / Replier | 把 PUB/SUB 与 REQ/REP 的样板收在一处 |
| `logkit.py` | 125 | 结构化日志，一行一条 JSON | 日志要能被脚本消费（`console.py` 就是靠它） |
| `config.py` | 79 | YAML 加载 + `include` + 点号取值 | `cfg.get("perception.ocr.backend", "rapid")` |
| `ids.py` | 68 | `run_id` / `event_id` / `cmd_id` / 序号 | `event_id` 是串起四条接口的主键（ICD §2.2） |
| `clock.py` | 57 | 单调钟 + UTC 双时间戳 | 算时延只能用单调钟，落盘只能用 UTC |
| `errors.py` | 33 | `DriverError` / `DriverNotReady` | 驱动层唯一的异常约定 |

### `patrol/schemas/` —— 冻结的接口（5 份 JSON Schema）

`detection_event` / `control_command` / `command_ack` / `status_report` /
`evidence_package`。全部 `additionalProperties: false`。
**改它们要走 `tools/validate.py` 的 `ALLOWED_DRIFT` 白名单流程**，不许静默加字段。

### `patrol/drivers/` —— 硬件抽象（1 966 行）

| 文件 | 行 | 干什么 |
|---|---|---|
| `base.py` | 365 | 四个 ABC：`IChassis` / `IPTZ` / `ICamera` / `ILocalizer` + 开机自检 |
| `factory.py` | 62 | **唯一的分支点**：`driver_mode: stub\|real` 在这里分叉 |
| `stub/chassis_stub.py` | 327 | 底盘桩：沿路线推进、注入 2 % ACK 丢包与安全事件 |
| `stub/ptz_stub.py` | 302 | 云台桩：真实角速度、稳态抖动、5 % 对焦失败、4K 裁剪仿真 |
| `stub/camera_stub.py` | 153 | 相机桩：调渲染器出图。**视点优先取 IF-3**，见 `observe_state` |
| `stub/pose_stub.py` | 115 | 定位桩：航位推算 + 可注入失锁 |
| `real/chassis_serial.py` | 221 | 真底盘：串口，只发任务级指令 |
| `real/serial_protocol.py` | 218 | 串口编解码（`docs/底盘串口协议.md` v0.1） |
| `real/ptz_serial.py` | 212 | 真云台：**到位判据比对目标值**，不信上一帧的 `at_target` |
| `real/localizer_serial.py` | 121 | 从底盘状态帧推位姿。`source` 恒为 `ODOM_ONLY`——车上没激光雷达 |
| `real/camera_v4l2.py` | 98 | V4L2 相机。时间戳取**曝光开始**，不是取回时刻 |
| `real/serial_link.py` | 82 | 串口链路薄封装 |

**桩不是占位符**：它注入真实的运动约束与故障率，所以"在桩上跑通"是有意义的
验收。赋值即到位的假驱动会让任何判据都显得正确。

### `patrol/scene/` —— 虚拟配电室（1 131 行）

| 文件 | 行 | 干什么 |
|---|---|---|
| `render.py` | 433 | 渲染器：位姿 + 云台角 + 变焦 → 一帧图 + 每个目标的 bbox（+ 可选掩膜） |
| `gauges.py` | 290 | 表计的程序化绘制。**RGB 与掩膜共用同一套比例常数** |
| `world.py` | 209 | 世界模型。`truth`（真值，只给渲染与打分）与 `priors`（先验，感知可读）**严格分开** |
| `optics.py` | 199 | `pixel_density` / `hfov` / `zoom_for_density`。全项目的光学公式只在这里 |

`world.py` 那条分界是整个评测可信度的地基：感知侧永远读不到 `truth`，
否则精度指标全是自己糊弄自己。

## 五、配置开关总表

全部在 `configs/system.yaml`，改完跑一次 `python -m patrol.tools.validate`。

| 键 | 取值 | 现在 | 什么时候改 |
|---|---|---|---|
| `driver_mode` | `stub` / `real` | `stub` | 真车到位 |
| `perception.detector` | `synthetic` / `yolo` | `synthetic` | YOLO 权重训出来 |
| `perception.segmenter.backend` | `builtin` / `npz` / `onnx` | `builtin` | 见 `bench_models` 的对比结论 |
| `perception.ocr.backend` | `rapid` / `off` | `rapid` | 引擎装不上时自动降级 |
| `perception.l3.model` | `efficientad_s` / 统计法 | 统计法 | L3 权重就位 |
| `mission.servo.mode` | `pid` / `open_loop` | `pid` | 对比演示时切 |
| `gateway.enable_ptz_rate` | 真 / 假 | 真 | A1 增补，未入冻结 Schema |

## 二、催甲（最紧，按依赖顺序做）

**现状**：巡航级训完了，mAP50 0.9949、mAP50-95 0.7513、召回 0.9976，五项验收里
这一项达成。**其余四项一项没动**，一页纸里还有 13 个 ⬜。

### 1. 先把权重放出来（10 分钟，最先做）

`deliverables/甲-检测/artifacts/where.txt` 现在写的是：

```
best_cruise.pt   ⬜ 甲补链接（原先误传进库里，已移出）   19 MB   ⬜
```

**这条不做，后面所有数别人都没法复核。**传网盘，把两个 ⬜ 换成链接和 sha256 前 8 位。

### 2. 训复核级（一条命令）

```bash
python -m training.train_detector --stage verify --device 0
```

数据集和环境都在你机器上（`args_cruise.yaml` 里的 `data.yaml` 路径还在）。
`verify` 用 `yolo11m` + `batch 8`，而你 `cruise` 用的是 `batch 4`——**显存不够先降 batch**，
别卡在 OOM 上。

验收标准原本是「mAP50 优于巡航级 ≥5 个点」，但巡航级已经 0.9949，**这条在当前数据集
上没有余量**。改口径的理由和写法在你的 [`避坑清单.md`](../deliverables/甲-检测/避坑清单.md) 第 7 节，
照那个写，别硬凑。

### 3. 补两个硬指标

| 指标 | 限值 | 怎么测 |
|---|---|---|
| 单帧耗时 | ≤ 33 ms | ultralytics `val` 的输出里有逐阶段推理耗时 |
| 漏检率 | ≤ 2 % | 同上，从混淆矩阵算 |

这两条是「巡航级能不能 30 Hz 跑」的判据，没有它们 mAP 再高也说明不了实时性。

### 4. 切换前后对比 —— **这一条比 mAP 重要**

它是「代码先行、模型后训」这条项目立论的唯一实证。现在 PPT 上写着这句话，
但没有数支撑。

```bash
# 权重放到这两个路径（configs/system.yaml:39-40 就指着它们）
#   training/runs/cruise/weights/best.pt
#   training/runs/verify/weights/best.pt

# 切换前
python -m patrol.tools.run_all --seconds 300 --quiet     # detector: synthetic
# 改 configs/system.yaml → perception.detector: yolo，再跑
python -m patrol.tools.run_all --seconds 300 --quiet
```

交一张表：证据包数 / 平均密度比 / Δconf / 复核成功率。**只要不退化就是成功**，
不需要变好。

⚠ **每边至少跑三轮取区间。** 组长实测三轮干净数据是 87.5 / 100 / 71.4 %——
单轮判这一项就是抽签。跑之前先清端口：

```bash
pkill -9 -f 'tools.run_all|cloud.server|patrol.(gateway|mission|perception|uploader).node'
sleep 4
```

没清干净时 cloud 和 perception 会直接退出，**而小结照样打印且看着正常**
（成功率 40 %、密度比 0.65）。`run_all` 现在会打横幅并以退出码 2 结束，看到就重跑。

### 5. 增广对比表

只用公开集 vs 公开集 + 合成集的 mAP。这是任务书要的方案比选证据。

### 6. 补三张复核级的图

`figures/` 里巡航级的七张都在了（`_cruise` 后缀）。复核级训完之后按 `_verify`

**不做的后果**：任务书第 3 项前半永远是 🔴，第 8 项的「识别效果」无从评估，
PPT 上「代码先行、模型后训」这条主线缺最后一步。

# 后续任务计划与分工书

**依据是任务书**（`22 基于RK3576边缘计算的无人车主动式AI巡检系统设计.docx`），
不是任何人的临时想法。任务书里没写的事，这份计划里也不写。

团队 4 人：**组长 1（答辩材料与交付）+ 组员 3（各训一类模型）**。

## 零、先说清楚前提

**硬件没有，也不会有。** RK3576 板子、无人车、云台、相机都不在。整套系统跑在
一台笔记本上：虚拟配电室按针孔投影渲染，驱动层由 `driver_mode` 一个开关切换。
这不是将就，是任务书"首版可先以单路 1080p RGB 相机和有限缺陷类别达成稳定闭环"
的落地方式——闭环先跑通，模型后填进去。

**所以答辩的重心是"边缘端能不能自己做决定、做完能不能拿出证据"，
不是"识别有多准"。** 这一条不依赖任何权重，每一步都能当场演示。

## 二、萌新上手：下载完项目后一步步做什么

**在动自己那一块之前，三个人都要先走完这一节。**大概两小时。
不走完就开工，你会不知道自己训的模型要接到哪里去。

### 第 1 步　装基础环境（约 10 分钟，80 MB）

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
```

只需要 Python 3.10+。**这一步不需要 GPU、不需要 torch。**

### 第 2 步　验证装好了（约 3 分钟）

```bash
python -m patrol.tools.validate     # 应当打印「51 项」全绿
python -m pytest -q                 # 应当是 502 条用例，绿的
```

**这两条不过就别往下走**，先解决环境问题。`validate` 查的是五份冻结 Schema
与代码的一致性——它红了说明接口对不上，后面所有事都建立在错误的地基上。

### 第 3 步　把系统跑起来看一遍（约 15 分钟）

开三个终端：

```bash
# 终端 1：起全系统（四进程 + 云端），跑 10 分钟
python -m patrol.tools.run_all --seconds 600 --console

# 终端 2：3D 车载视角，跟着真实系统走
python -m patrol.tools.viewer --live

# 终端 3：第三人称，能看见车和云台视锥，可键盘操作
python -m patrol.tools.viewer --thirdperson
```

浏览器打开 <http://127.0.0.1:8000>。

> 三个系统上都是同一条命令，不用再加 `DISPLAY=win` 前缀。viewer 按平台
> 判断能不能开窗：Windows 与 macOS 直接开，Linux 才看 DISPLAY。要存帧
> 不开窗用 `--headless --out out/`。

**要看懂的四件事**（看不懂就去问，别硬往下做）：

1. **指令流水**里一次完整复核长什么样：
   `PTZ_RATE ×N → PTZ_SET 变焦 → PTZ_SET 归位 → RESUME`。
   变焦倍率是按当前像素密度算出来的，不是写死的常数。
2. **车载视角**里橙框=像素密度不达标需复核，绿框=达标。
   巡航时大多是橙的——这就是"必须停车变焦"的理由。
3. **第三人称**里按住 `E` 变焦，视锥从 60° 收到 21.8° 并套住一块表。
   这是整个项目的立论，一定要亲眼看一次。
4. **浏览器台账**里点开一条证据包：cruise 一张 + verify 三张 + ROI，
   还有 Δconf、密度比、状态机各段耗时。

键位：`A/D` 转云台，`W/S` 俯仰，`Q/E` 变焦，`空格` 暂停行驶，
`H` 归位，`R` 强制安全事件，`L` 强制失锁，`ESC` 退出。

### 第 4 步　读三份文档（约 40 分钟）

按顺序，**别跳**：

1. `docs/新手上路.md` —— 这个仓库是干什么的
2. `docs/架构说明.md` —— 四进程、四条接口（IF-1~IF-4），你的模型接在哪一环
3. `training/README.md` —— 数据从哪来、为什么不能拿合成集训检测器

然后看一眼 `docs/代码地图.md` 找到自己那部分代码在哪。

### 第 5 步　装训练依赖（约 30 分钟，2.5 GB）

```bash
pip install -r requirements-yolo.txt      # 含 torch，很大，先装上别等
```

**三个人都要装**，即使你训的不是 YOLO——`train_segmenter` 和 `train_anomaly`
的部分通路也依赖它。装完确认能看到显卡：

```bash
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

打印 `False` 就先解决驱动/CUDA，别用 CPU 硬训。

### 第 6 步　确认自己的训练脚本能跑起来

各自跑一遍 `--help`，确认没有 import 错误：

```bash
python -m training.train_detector --help
python -m training.train_segmenter --help
python -m training.train_anomaly --help
```

### 第 7 步　看清楚自己要下什么数据

```bash
python -m training.prepare_dataset --list
```

它会打印每个数据集的**下载地址、许可、规模，以及该放到哪个目录**——照着放，
不用猜路径。下完之后：

```bash

```

## 三、三个人怎么分

**每人一类模型、一张卡、一条独立的数据来源**，互不阻塞。

三条通路在系统里的位置见 `docs/多模型协同.md`：L1 负责"看见有东西"，
L2 负责"读出数值"，L3 负责"说不出是什么但不对劲"。

### 甲 · L1 检测模型（`training/train_detector.py`、`perception/detector/`）

对应任务书第 3 项前半。**这是唯一的硬缺口，也是关键路径。**

| 任务 | 验收标准 |
|---|---|
| 注册 Roboflow，下 `distribution_room`（2773 张，CC BY 4.0） | `python -m training.prepare_dataset --check` 全绿 |
| 训巡航模型（小、快） | 验证集 mAP50 ≥ 0.70，单帧 ≤ 33 ms |
| 训复核模型（大、准） | mAP50 优于巡航模型 ≥ 5 个点 |
| 导 ONNX，改 `perception.detector: yolo` 接进链路 | `run_all` 跑一轮，不退化于合成检测器 |
| 合成集做增广，对比开与不开 | 一张表：只用公开集 vs 公开集+合成集 的 mAP |

```bash
python -m training.prepare_dataset --to-yolo               # 先转成 YOLO 格式
python -m training.train_detector --stage cruise --device 0   # 巡航模型
python -m training.train_detector --stage verify --device 0   # 复核模型
```

**`--device` 指定用哪张卡**（`0`、`1`，多卡写 `0,1`，没卡写 `cpu`）。
三个人各占一张，别都用默认的 0——那样会互相抢显存。

**两个坑**：
- `DetectionEvent.model.name` 枚举只有 `yolo11s` / `yolo11m`。要报别的名字得走
  `validate.py` 的 `ALLOWED_DRIFT` 流程，**不许静默塞值**。
- **权重从公开数据集训，不要从合成集训。** 合成数据补的是密度分层，不是纹理
  多样性；拿合成集训的权重上真机，sim-to-real gap 会把指标吃掉一大截。
  理由见 `training/README.md`。

**第一天先出一个 100 张的小批次**，让乙丙能拿去跑通各自的流程，别等全量下完。

### 乙 · L2 分割模型（`training/train_segmenter.py`、`perception/segment/`）

对应任务书第 3 项里的读数通路。**现在读数走几何法，学习法是要和它比的对手。**

| 任务 | 验收标准 |
|---|---|
| 下 PaddleX 工业表计读数数据集（检测 783 / 分割 414，百度官方直链） | `--from-paddlex` 跑通，**人眼看 `check/` 里的叠加图**确认掩膜没错位 |
| 用合成掩膜先跑通链路 | `gen_synthetic` → `train_segmenter` → `npz` → 接进读数链 |
| 用真实标注重训 numpy 基线，对比针的 IoU | 现在只有 **0.182**，看真实数据能提到多少 |
| **训一个 U-Net 去打这个基线**（你的显卡花在这里） | IoU 明显优于 0.182，且接进读数链后误差不劣于几何法 |
| 跑 `bench_models.py` 按像素密度分档 | 结论表：每一路该用哪个实现，**用数据说话** |

```bash
# --preview 会另存几张把标注画回图上的核对图，**一定要人眼看一遍**
python -m training.gen_synthetic --n 300 --out training/datasets/synth --preview 8
python -m training.train_segmenter --data training/datasets/synth
# → training/runs/seg/pixel.npz，把 perception.segmenter.backend 改成 npz

# 真实数据到手后
python -m training.prepare_dataset --from-paddlex training/datasets/paddlex_meter
```

**要理解的关键一点**：现在 `backend: builtin`（几何法）是**用数据定下来的默认**，
不是偷懒——`bench_models` 实测几何法 0.05 %FS / 2.4 ms，级联分割 0.11 %FS /
5.5 ms，更准一倍还快 2.4 倍。你的任务不是"证明学习法更好"，是**给出一个诚实的
对比结论**。学习法真的赢不了，那结论本身就是成果。

> ⚠️ **注意 `train_segmenter` 没有 `--device` 参数**——它训的是一个 numpy
> 逻辑回归，不用 GPU，几分钟就跑完。这是刻意的：它的作用是把「造数据 → 训练
> → 导出 → 推理 → 接进读数链」这条链路完整跑通，并留下一个诚实的基线。
>
> **所以你的显卡是花在第二步的**：拿 PaddleX 的真实分割标注训一个 U-Net，
> 去打 0.182 这个基线。先跑通 numpy 基线（半天），再上 U-Net——顺序别反，
> 链路没通就直接上大模型，出了问题分不清是模型的锅还是接线的锅。

学习法的价值在几何法假设不成立时：方形表、指针与背景同色、玻璃反光盖住半个盘面。
真实数据集里如果有这类样本，重点测它们。

### 丙 · L3 异常检测模型（`training/train_anomaly.py`、`perception/anomaly.py`）

对应任务书第 3 项的"未知异常检测"，任务书点名 **EfficientAD / PaDiM**。

**你是三个人里唯一第一天就能开工的**——正常样本本地就能生成，不用等下载。

| 任务 | 验收标准 |
|---|---|
| 生成正常样本集 | `gen_synthetic` 产出 L3 正常集 |
| 训 EfficientAD（或 PaDiM），接上现成接口 | `EfficientADAnomaly` 接口已就位，只等权重 |
| 与现有统计法对比 | 一张表：统计法 vs 学习法的误报/漏报，**在同一批样本上** |
| 导 ONNX + `export_rknn.py` 导出链路 | 导出成功 + ONNX 冒烟推理，INT8 掉点记录在案 |
| 量化校准集从 `evidence/` 取本场景图 | **不许用 COCO 之类通用图校准**，掉点会明显偏大 |

```bash
python -m training.gen_synthetic --n 300 --out training/datasets/normal_patches
python -m training.train_anomaly --data training/datasets/normal_patches --device 1

# 更好的一条路：直接拿跑出来的证据包当正常样本，比合成的更接近真实分布
python -m patrol.tools.run_all --seconds 300          # 先攒一批证据
python -m training.train_anomaly --from-evidence evidence/ --device 1
```

`--backend` 可选 `auto` / `efficientad` / `statistical`，默认 `auto`：
依赖装齐就走 EfficientAD，装不齐自动退回统计法——**所以装不上也不会卡住你**。

**要理解的关键一点**：非监督，**只用"看起来正常"的样本**。这正好绕开任务书
提到的数据可得性约束——室内配电室的渗漏油、呼吸器变色几乎没有公开标注数据，
但"正常设备的图"要多少有多少，巡检跑一轮就攒下一批。

现有的 `StatisticalAnomaly` 是在线学习 + 马氏距离，**零权重、当场能跑、而且
可解释**（异常分来自哪个特征通道说得清）。你训出来的学习版要赢它才有意义——
赢不了也是结论，写清楚即可。

## 五、每次改完代码的固定动作

不管谁改，改完这三条必须跑：

```bash
python -m patrol.tools.validate    # 51 项接口一致性，这条不过就别提交
python -m pytest -q                # 502 条用例，一条都不许退化
python -m patrol.tools.run_all --seconds 300   # 端到端，看小结的密度比与 Δconf
```

**496 是收集数，不是通过数。**三处可选依赖会把用例转成 skip 而不是 fail：
`test_cloud.py` 依赖 fastapi、`test_ocr.py` 依赖 OCR 引擎、`test_serial_protocol.py`
有一条依赖 pyserial。所以不同机器上报的 "passed" 本来就不同——**比对基线时看
收集数，skip 数单独记**，否则少 34 条到底是有人删了测试还是这台机器没装 fastapi，
光看 passed 分不出来。

另外，套件里有一族测试的结果与机器负载相关（桩用后台线程按墙上时钟推进仿真）。
这类已经处理过一轮，判据与工具见 `tests/conftest.py` 里 `_wait_until` 与 `_retry`
的说明——**能等事实就不要重试测量**。

## 六、风险与预案

| 风险 | 预案 |
|---|---|
| **甲训不出可用权重**（没 GPU、数据质量差、时间不够） | **第 2 周结束是止损点**：退回合成检测器，把"代码先行、模型后训"当结论讲。这条路的成立性已经有据可依，不是临时找补 |
| PaddleX 直链下不动 | 乙退回合成掩膜，结论改成"链路跑通 + 合成集基线"，如实说明缺真实数据 |
| EfficientAD 依赖装不上 | `train_anomaly` 有两条通路，按依赖是否装齐自动选；退回统计法，它本来就零权重可跑 |
| 板子到货 | 第 2 项立刻从 🔴 转 🟡：跑 `export_rknn.py` 上板冒烟 + 测速，INT8 掉点记录在案 |

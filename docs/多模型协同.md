# 多模型协同识别

这份文档回答一个问题：**为什么"把识别做好"不是训一个更大的 YOLO，而是让
四类性质不同的模型配合起来。**

读之前先看 `docs/架构说明.md` 的"关键数据流：一次复核"，这里讲的是那条数据流
里"识别"那一段的内部结构。

---

## 一、识别拆开是四个不同的问题

"这块表有没有问题"听上去是一个问题，做起来是四个，而且**它们要的东西互相
打架**：

| 问题 | 要回答的 | 模型类别 | 为什么不能合进一个模型 |
|---|---|---|---|
| **在哪** | 画面里有哪些设备，框在哪 | 目标检测 | 要快、要全图扫。巡航期 30 Hz 只跑得起它 |
| **多少** | 指针指向几、液位到哪 | 语义分割 + 几何解算 | 要像素级精度。只在放大后的小 ROI 上跑得起 |
| **写的什么** | 铭牌量程、单位、位置指示牌 | OCR（检测 + 识别） | 输出是字符串不是数，损失函数与评价指标都不同 |
| **没见过的** | 训练集里根本没有的异常 | 非监督异常检测 | 有监督模型对未知类别**系统性沉默**，不是识别错，是压根不吭声 |
| **信谁** | 四路证据打架时怎么办 | 显式规则仲裁 | 必须能逐条讲清"凭什么"，评审第一个问题就是这个 |

一个模型全干的代价不是"精度差一点"，是**每一路都被别的路拖到跑不动或学不会**：
要 30 Hz 就不能像素级，要像素级就不能全图扫，要认字就得换一套输出头，要认
没见过的就不能用有监督的损失函数。

### 这个拆法不是新加的概念

ICD 早就把位置留好了，只是一直没人填：

- `detection_event.schema.json` 里 `trigger_rule` 的枚举是
  `CONF_BAND / L2_UNREADABLE / L2_OUT_OF_BAND / L3_ANOMALY / …`
  ——**L1 / L2 / L3 这个三级判据阶梯本来就写在协议里**
- `l2_reading.kind` 的四个取值 `POINTER_GAUGE / DIGITAL_DISPLAY /
  INDICATOR_LIGHT / SWITCH_POSITION`，恰好对应四种完全不同的"读数"方式
- `evidence_package.schema.json` 的 `verdict.result` 六个取值
  `CONFIRMED_DEFECT / FALSE_ALARM / READING_OK / READING_ABNORMAL /
  UNKNOWN_ANOMALY / INCONCLUSIVE`，正是一个仲裁层该有的六种结论
- `files[].role` 里已经有 `VERIFY_ROI` / `ANOMALY_HEATMAP` /
  `VERIFY_FRAME_AUX`，分割叠加图、OCR 截图、异常热力图都有合法归属

所以这一层**没有改任何 Schema**，是把协议里已经画好的格子填满。

## 二、五种协作关系

讲思路时按这五条讲，每一条都能在代码里指到具体位置。

### 1. 级联 —— 快的筛，慢的判

巡航期只跑 L1 检测（小模型、INT8、640 输入），复核期才跑 L2/L3
（大模型、FP16、960 输入）。同一个 `IDetector.infer(stage=…)` 接口，两套
权重，`DetectionEvent.model` 如实上报这一帧跑的是哪套。

**这个划分本来就在架构里，多模型协同是白捡的。**巡航/复核两段式原本是为了
省电和省时间；一旦有了它，"快模型"和"重模型"的分工就是现成的。

### 2. 接力 —— 后一级只处理前一级圈定的像素

```
检测给出 bbox → 分割只在这个 ROI 上跑 → 几何解算把针角变成读数
```

代价从全图降到 ROI。`patrol/perception/node.py::_l2_read` 就是这条接力的
交接点。

分割与几何的接力更细：**分割替换掉的只是"哪些像素是针"这一步**，也就是几何
法里假设最强的那一步（它假设针是盘面上最暗的贯穿条）。极坐标展开、逐环角
质心、180° 歧义消解全都照旧复用——**亚度级精度是几何算出来的，不是学出来
的**。学习模型给不出 0.25° 的角分辨率，而那正是 0.5 % FS 精度所依赖的。
见 `reading/pointer.py::_needle_angle` 的 `prob_rect` 参数。

### 3. 互证 —— 同一个数由两条独立通路给出

这是四路里最容易被忽略、但价值最高的一条。

**几何法读指针是从像素里量角度，量得再准也回答不了一个问题：这块表的量程
到底是多少。**量程来自标定表，而标定表是人录的。录错了、或者车停错了航点
看错了柜子，几何法算出的 0.85 MPa 会是一个**看起来完全正常**的错值，没有
任何征兆——报出去没人会去查。

表盘上其实印着答案：刻度数字和单位就画在表面上。OCR 把它们读出来，就得到
一份**与标定表相互独立**的量程与单位。

| 目标 | 通路 A | 通路 B | 对不上说明什么 |
|---|---|---|---|
| 指针表 | 几何法量角度 → 读数 | OCR 读刻度数字与单位 → 量程 | 标定错配，或车站错了地方 |
| 开关把手 | 几何法量把手朝向 → 分/合 | OCR 读位置指示牌 → ON/OFF | 两路必有一路错，交人 |
| 数显表 | —— | OCR 直接读数字 | （只有一路，置信度低一档） |

方案书表 2-2 要求开关分合位正确率 ≥ 99 %。靠单一通路很难说清"凭什么"，
两路互证才有话可讲。

### 4. 兜底 —— 每一路都能缺席，链路不能断

- 学习模型没权重、置信度低、ROI 太小 → 自动退回几何法/统计法
- OCR 引擎装不上 → `build_ocr` 返回 `DisabledOcr`，互证降级但读数照常
- 分割给不出可用掩膜 → `read_pointer_gauge` 退回纯几何

**缺席让结论变保守（置信度打折、needs_human_review 抬起来），而不是让链路
崩掉。**一个可选依赖不该把整台车的感知拖停。

L3 兜的是另一种缺席：**检测器压根没有这个类别**。外物、渗油、锈蚀的新形态，
有监督模型对它们不是判错，是完全不吭声。非监督异常检测填的正是这个洞。

### 5. 仲裁 —— 四路证据合成一个结论，并说清凭什么

`patrol/perception/fusion.py`。**这一层没有权重，是纯规则的，而这是刻意的
选择。**

前三层都可以是学出来的黑箱，因为它们的输出还能被下一层质疑。但最后这一步
的产物要进证据包、要送到人面前、要作为"这台设备有没有问题"的记录留档。
评审第一个问题一定是"凭什么"，而一个学出来的融合网络对这个问题的回答只能是
"它就是这么算的"。

所以每条结论都带 `reasons`，原样进 `meta.jsonl`：

```
READING_OK  conf=0.959
   开关位置两路一致（几何法 CLOSED、位置牌 ON）
   读数 CLOSED 落在正常带内 → READING_OK
```

## 三、四路证据的可信度排序

这个顺序是整层的核心，排错了每一条都有实测后果。

| 序 | 规则 | 排错的后果（都是实测出来的） |
|---|---|---|
| 0 | 复核中止 → `INCONCLUSIVE` | —— |
| 1 | **互证冲突压过一切** | 量程错配时读数看起来完全正常，报出去没人会查 |
| 2 | 观测条件不足时不下读数类结论 | 像素密度没到 120 px 就谈读数精度是自欺欺人 |
| 3 | **有读数就以读数为准，L3 排在它后面** | 排反了：一整轮压力表全被判 `UNKNOWN_ANOMALY`，读数通路白做 |
| 4 | 没有读数时 L3 才出面，且只进人工队列 | ICD §3.1：L3 输出不得直接告警 |
| 5 | 复核后置信度够高 → `CONFIRMED_DEFECT` | —— |
| 6 | 置信度被复核打下去 → `FALSE_ALARM` | 一级为保召回压到 0.25 必然带来误报，消解掉正是立论所在 |
| 7 | 都不足以定论 → `INCONCLUSIVE`，交人 | **证据不足就说不足，不猜**——和网关"拒绝而非截断"是同一条原则 |

### 结论置信度怎么算

刻意保持单调、有界、可口算——评审能自己按着算一遍，这比多零点几个点的
AUC 值钱：

```
base = 检测置信度；有读数时与读数置信度各占一半
互证一致 → base += (1 − base) × 0.25      把剩余不确定性砍掉 1/4
互证冲突 → base × 0.50
证据不足 → base × 0.96                    跑了但没读清楚
完全缺席 → base × 0.92                    这一路没跑
成像质量分 < 0.5 → 再 × 0.9
```

## 四、最难的一课：互证通路差点成了最大的误报源

这段值得单独写，因为它是这一层唯一一次把系统指标打崩的改动，也是**多模型
协同最容易踩的坑**：*多一路模型，就多一个会说错话的嘴。*

接上 OCR 的第一版，判据是"OCR 读到的数字对不上先验量程 → 判标定错配"。
听上去无懈可击。端到端一跑，**复核成功率从 100 % 掉到 28.6 %**——7 个证据包
里 5 个被自己的互证通路判成了 `INCONCLUSIVE`。

两个原因：

**一、两条通路用的是两套词。**几何法报 `CLOSED`/`OPEN`（合闸/分闸），位置牌
印的是 `ON`/`OFF`。直接比字符串，于是"几何法 CLOSED vs 位置牌 ON"——两路其实
完全一致——被判成互相矛盾，一轮里 6 个开关证据包全部误标。
修法是归一到同一套词（`nameplate.canon_switch_state`）。

**二、举证责任的方向错了。**实测一块 120 px 的表，RapidOCR 会把 `0.4` 读成
`4`、`1.2` 读成 `12`——**小数点是第一个丢掉的东西**。按"对不上就翻脸"判，
好表被判成标定错配，复核预算白烧一次，一条工单推到人面前。

第二条改了三轮：

1. 加识别置信度门槛 → 不够。OCR 对**字符**很自信，对**语义**不自信
2. 加小数点丢失检测（整批 ×10 后落回先验刻度就判为噪声）→ 好些了，
   但半对半错的结果（`[0.8, 2.0, 2.4, 10.0]`）照样翻脸
3. **把判据倒过来**：只有当读到的数字**自身构成一套自洽的等距刻度**、
   且这套刻度指向另一个量程时，才判冲突

第三条才是对的。举证责任应当是"**证明这是别的表**"，不是"证明这些数字对不上
先验"。两者听起来相近，代价完全不同：噪声凑不出自洽刻度，真看错表则一定
凑得出（0–6 的表读到 `0/1.5/3/4.5/6`，公差 1.5、共 4 格，隐含量程 0–6）。
改完复核成功率回到 100 %。

留下的纪律写进了 `CrossCheck.agree` 的三态：

```
True   一致    → 佐证，置信度上抬
False  冲突    → 反证，压过读数，交人
None   证据不足 → 既不佐证也不反证，只让结论保守一档
```

**"证据不足"和"冲突"是两件事，混为一谈的代价是 71 个百分点的复核成功率。**

## 五、每一路选了什么，为什么

沙箱网络实测决定了什么能真跑：PyPI 可达、GitHub release 资产可达、
**`download.pytorch.org` 与 `huggingface.co` 不可达**——torchvision 预训练
权重和一切 HF 托管模型都拿不到。

**统一运行时选 ONNX Runtime**（PyPI 23 MB，不依赖 torch）：训练侧想换框架
就换，部署侧不变；RK3576 的 RKNN 工具链吃的正是 ONNX；组里同学不装 527 MB
的 torch 也能跑通全链路。

| 层 | 接口 | 今天就能跑（无权重） | 接学习模型 | 配置键 |
|---|---|---|---|---|
| L1 检测 | `IDetector` | `SyntheticDetector` | `YoloDetector` / ONNX | `perception.detector` |
| L2 分割 | `ISegmenter` | `builtin`（几何法，默认） | `NpzSegmenter` / `OnnxSegmenter` | `perception.segmenter.backend` |
| L2′ OCR | `IOcr` | `DisabledOcr` | **`RapidOcr`（已在跑）** | `perception.ocr.backend` |
| L3 异常 | `IAnomalyDetector` | `StatisticalAnomaly` | `EfficientAD` 等 | `perception.l3.model` |
| L4 融合 | —— | 规则，无权重 | —— | `perception.fusion` |

**OCR 是目前唯一一个从安装到推理完整可跑的学习模型**：
`rapidocr-onnxruntime` 15 MB 的包里自带 ONNX 权重（DBNet 检测 + CRNN 识别），
装完不联网就能用，不依赖 torch。

## 六、没有标注数据这件事，被渲染器解决了

方案书 §2.4.5 承认了一个绕不开的约束：配电室缺陷没有公开的标注数据集，
尤其是像素级的。而读数通路要的恰恰是像素级——指针占几个像素、边界在哪，
直接决定读数误差。真实标注一块表盘要人描十几分钟，四百张就是一周。

渲染器把这件事变成免费的：**图是按几何画出来的，所以画的时候就知道每个
像素属于谁。**`render_pointer_gauge_mask` 用与 RGB **同一套比例常数**把
针/面/刻度画到标签画布上，再经 `render(want_mask=True)` 走同一次透视变换
——掩膜与图像天生逐像素对齐，不需要任何配准。

`python -m training.gen_synthetic` 一次产出四种标注：

```
labels/    YOLO 检测框            → L1
masks/     针/面/刻度 三类掩膜      → L2
ocr.jsonl  表盘 ROI 与其上印着的字  → L2′ 的评测集
normal/    无缺陷裁片              → L3 的正常集
```

### 采样按像素密度分层，不是按位置均匀撒

这是数据侧最关键的一个决定。整套方案的立论是"5 m 处 1× 只有 50 px 读不准，
所以要停车变焦到 120 px"，**训练集必须同时覆盖这两段**。

第一版按位置均匀撒，自检报告直接打脸：`低于判据线 99 %`。原因是过道到柜面
5.00 m，一块 0.18 m 的表在 3× 也只到判据线，而多数（航点, 目标）对比这更远。
改成先抽目标密度、再从"够得着这个密度"的组合里挑，两段才真的都覆盖到
（实测 43 % / 57 %）。

### 诚实的边界

合成数据训出来的模型在真实配电室上**会有 sim-to-real gap**。这里的域随机化
只有位姿/角度/变焦/光照/运动模糊/高光这几维，纹理和背景的多样性远不如真实
场景。正确的用法是拿它做预训练与算法验证，真机数据到了再微调。
**别拿合成集上的 mAP 去当验收指标。**

## 七、用数据决定每一路开不开

`python -m patrol.tools.bench_models`

**这个工具的存在本身就是一个立场：多模型协同不是"模型越多越好"。**每加一路
都要付出代价——推理时间、内存、一个会失效的新组件、以及一条新的"两路说法不
一致时怎么办"的规则。所以每一路都得回答同一个问题：*它到底把什么指标变好了
多少*。答不上来的那一路就该关掉。

实测（本机，合成表盘，按像素密度分档）：

**读数**

| 像素密度 | 几何 %FS | 耗时 | 级联 %FS | 耗时 |
|---|---|---|---|---|
| 30–60 px | 0.05 | 2.3 ms | 0.06 | 5.6 ms |
| 90–120 px | 0.08 | 2.3 ms | 0.06 | 5.2 ms |
| 120–180 px | 0.14 | 2.4 ms | 0.12 | 5.5 ms |

→ **级联与几何法持平而慢 2.3 倍，所以 `segmenter` 默认 `builtin`。**
学习法的价值在几何法的假设不成立时（方形表、指针与背景同色、反光盖住半个
盘面），那类样本现在还没有——等真机数据到了重新比一次再决定。

**OCR 互证**

| 像素密度 | 判一致 | 证据不足 | 误判冲突 |
|---|---|---|---|
| 30–60 px | 0 | 6 | **0** |
| 60–90 px | 0 | 6 | **0** |
| 90–120 px | 4 | 2 | **0** |
| 120–180 px | 6 | 0 | **0** |
| 180–320 px | 5 | 1 | **0** |

→ 这张表同时说明两件事：**字要 90 px 以上才读得出**（与指针那一路 120 px
的判据线互相印证——两者受制于同一个东西）；以及**误判冲突全档为 0**，
第四节那套举证门槛是有效的。

**耗时**

复核期四路合计 281 ms（预算 3000 ms），巡航期只跑 L1。预算是够的。

## 八、怎么看四路模型在跑

三个显示面，一份数据源（见 `docs/操作步骤.md`）：

```
python -m patrol.tools.run_all --console      # 系统 + 终端指令流水
python -m patrol.tools.viewer --live          # 预览窗口，叠加指令与模型输出
浏览器 http://127.0.0.1:8000/ 「实时」页       # 指令流水 + 配电室俯视图
```

四路模型的逐条判断在两个地方：

- `evidence/<run_id>/<event_id>/fusion.json` —— 融合的完整证据链
- `evidence/<run_id>/<event_id>/meta.jsonl` —— IF-1/IF-3 原始报文，可逐帧重放

```bash
# 看一轮里每个证据包的结论和它的理由
for f in evidence/*/*/fusion.json; do
  python -c "import json,sys; d=json.load(open(sys.argv[1]))
for t,v in d['by_track'].items():
    print(v['result'], '%.3f'%v['confidence'])
    [print('   ', r) for r in v['reasons']]" $f
done
```

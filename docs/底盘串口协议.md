## 0　为什么先定这一版

原来的理由是"硬件未到、固件情况不明，先定一版最小可用的"。**现在固件源码到手了，
情况比预想的更需要这份协议**：

> **实车底盘 `XiaoChe_APM32` 完全没有串口指令通路。**`Source/User/` 下
> `grep USART|UART` 零命中，唯一的控制入口是 PS2 无线手柄；底层只有
> `calculateWheelSpeeds(vx, vy, omega, ...)` 这样一个速度级接口，四个麦轮
> 的转速走 CAN 下发。

所以这份协议不是"交给硬件组去实现的需求"，而是**我们自己要在这块 APM32 上写的
那一层**。好处是源码在我们手上，可以严格按 ICD §4.1 把适配层落在底盘 MCU 上——
RK3576 与底盘之间的链路上永远不会出现 vx / vy / ω 这类量。

实现清单与优先级见 `docs/底盘固件评审.md` §7–§8。上位机这一侧
（`patrol/drivers/real/chassis_serial.py`）与假小车（`patrol/tools/fakecar.py`）
已经写好并跑通，APM32 那边写完可以直接对拷验证。

**这一版只覆盖任务级指令。**协议里刻意不存在转向角、轮速、扭矩、制动力、
目标速度这类量，与 ICD §4.1 的白名单一致：AI 侧没有任何字段可以直接指定
车怎么动，只能表达"想停"和"想去某个已标定的点"。怎么停、怎么走由底盘自己
决定。

**这条待决事项已经有答案了：本车确实只有速度接口，所以适配层写在 APM32 上。**
理由是安全边界：一旦速度指令出现在 RK3576 与底盘之间的链路上，"AI 无法直接
控制车辆运动"这条就不再由协议保证，只能靠代码评审保证，而后者是靠不住的。

实车的几个数（`can_motor.c` 第 230–234 行，已核对）：

| 参数 | 值 | 备注 |
|---|---|---|
| 轮径 / 轮半径 | 0.2054 m / 0.1027 m | |
| 对角轮距 | 0.5165 m | 固件里 `L = 对角轮距/√2 = 0.3652 m`，是 **lx+ly**，不是注释写的"中心到轮" |
| 最高车速 | **0.1 × (gear+1)，最高 0.30 m/s** | 瓶颈是固件里 `MAX_SPD` 这个宏，不是电机 |
| 电机限幅 | 210 rpm | 对应轮周速 2.26 m/s，远未用满 |
| 底盘类型 | 麦克纳姆四轮，**可横移** | 靠近柜面不必转身 |
| 里程计 | 电机 CAN 回报 rpm 与 position（0x97–0x9A） | 轮式里程计可做，`CRP` / `GTO` 依赖它 |
| 现有 deadman | PS2 掉线约 250 ms 停车 | 与本协议 §4 的保活是同一类机制，复用即可 |

**PS2 手柄要保留，且优先级高于串口**——现场调试和出事时人工接管都靠它。
建议固件里加一个"遥控/自动"模式位，手柄任意输入即抢占为遥控模式。

## 1　物理层

| 项 | 值 | 说明 |
|---|---|---|
| 接口 | RS-485 半双工 / TTL UART | 差分优先，配电室电磁环境差 |
| 波特率 | 115200 | 8N1，无流控 |
| 隔离 | 光耦或磁耦，≥2500 V | 电机启停的浪涌不得串入主控 |
| 走线 | 与图像信号线分开，交叉处垂直 | 减少感性耦合 |

## 2　帧格式

一行一帧，ASCII，`\n` 结尾。选文本不选二进制的理由：出问题时可以直接用
`cat /dev/ttyUSB0` 看，学生项目里这点比省几个字节重要得多。

```
$<TYPE>,<seq>,<payload...>*<CRC8>\n
```

| 字段 | 说明 |
|---|---|
| `$` | 帧起始 |
| `TYPE` | 3 字符指令码，见第 3 节 |
| `seq` | 0–65535 十进制，回绕。用于对应指令与回执、检测丢帧 |
| `payload` | 逗号分隔，各指令不同 |
| `*CRC8` | `$` 与 `*` 之间所有字符的 CRC-8（多项式 0x07，初值 0x00），两位大写十六进制 |

校验失败的帧一律丢弃，不回执，不猜。上位机靠超时发现。

## 3　指令集

### 3.1 上位机 → 底盘

| TYPE | payload | 语义 | 对应 ICD 白名单 |
|---|---|---|---|
| `PAU` | `reason` | 请求停车 | `PAUSE` |
| `RES` | — | 恢复原巡检路线 | `RESUME` |
| `CRP` | `distance_mm` | 沿当前路径小步前移 | `CREEP_FORWARD` |
| `GTO` | `waypoint_id,tolerance_mm` | 前往已标定观察位 | `GOTO_OBSERVE` |
| `QRY` | — | 查询状态（底盘也会主动周期上报） | — |
| `PNG` | — | 链路保活 | — |

`distance_mm` 上限由底盘固件自己再限一道（建议 500 mm）。**上位机已经限过
一次，底盘再限一次，两道独立**——这是纵深防御，不是冗余。

### 3.2 底盘 → 上位机

| TYPE | payload | 说明 |
|---|---|---|
| `ACK` | `seq,result[,detail]` | 指令回执。`result` ∈ `OK` / `REJ` / `BUSY` |
| `STA` | 见 3.3 | 状态上报，20 Hz 周期 |
| `SAF` | `event,severity,brake_ms,detail` | 安全事件，**不等周期立刻发** |

### 3.3 `STA` 状态帧

```
$STA,<seq>,<state>,<speed_mmps>,<progress_permille>,<dist_to_goal_mm>,
     <waypoint>,<battery_permille>,<safety_active>*<CRC8>
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `state` | enum | `MOVING` / `STOPPING` / `STOPPED` / `PAUSED` / `RETURNING` / `FAULT` / `ESTOP` |
| `speed_mmps` | int | 当前线速度，毫米每秒 |
| `progress_permille` | int | 本轮路线完成比例，千分比 |
| `dist_to_goal_mm` | int | `GTO` 执行中的剩余距离，无目标时 `-1` |
| `waypoint` | str | 当前或最近的巡检位，无则 `-` |
| `battery_permille` | int | 电量千分比 |
| `safety_active` | 0/1 | 底盘安全层是否正在介入 |

**`STOPPING` 与 `STOPPED` 必须区分。**上位机的 `HALT_REQ` 状态等的是
`STOPPED`，收到 `STOPPING` 会继续等。合并成一个状态会让上位机在车还没停稳
时就开始变焦抓拍，拍出来全是糊的。

### 3.4 `SAF` 安全事件帧

```
$SAF,<seq>,<event>,<severity>,<brake_ms>,<detail>*<CRC8>
```

`event` ∈ `OBSTACLE_DETECTED` / `BUMPER_HIT` / `ESTOP_PRESSED` / `TILT_LIMIT`
/ `MOTOR_FAULT` / `LOW_BATTERY`

`brake_ms` 是**实测**的从事件发生到制动生效的时延，不是标称值。这条指标
（≤100 ms）由底盘安全层保证，不由 AI 侧保证；上报它是为了让这条指标可验收。
真机报出超过 100 ms 的值时，上位机照常记录并抛 SafetyEvent，**不会因为超限
就把报文丢掉**——那样恰好丢掉了最该留证的证据。

## 4　时序约定

| 项 | 值 |
|---|---|
| 状态上报周期 | 50 ms（20 Hz） |
| 安全事件 | 事件发生后 ≤20 ms 内发出，不等周期 |
| 指令回执 | 收到指令后 ≤50 ms 内回 `ACK` |
| 保活 | 上位机 ≥1 Hz 发 `PNG`；底盘 3 s 收不到则自行减速停车 |

最后一条是底盘侧的独立保护，与 RK3576 上的网关看门狗是两回事：网关看门狗
管的是"AI 进程死了"，底盘保活管的是"串口断了或整个 RK3576 死了"。两级都要有。

## 5　对接清单

已经有答案的（读固件读出来的）：

- [x] ~~底盘是否支持任务级指令~~ → **不支持，只有 (vx, vy, ω)。适配层写在 APM32 上**
- [x] ~~底盘安全层是否独立生效~~ → PS2 掉线约 250 ms 自行停车，机制已有
- [x] 巡检位编号在底盘侧如何存储 → 需新增，存 APM32 的 flash，**不由上位机下发**

还需要确认的：

- [ ] `STOPPING` / `STOPPED` 两个状态可区分（需要在新写的适配层里显式建模，
      当前固件只有"发速度"和"发 0"两种，没有减速中的概念）
- [ ] 急停按钮的解除方式（协议里 `ESTOP` 状态不可由指令清除）。当前固件里
      没有急停按钮，只有 PS2 的 START 键与掉线保护
- [ ] 制动时延实测值（`SAF` 帧的 `brake_ms` 要报真数，不是标称值）
- [ ] 引出哪一路 USART、电平（RS-485 / TTL）、连接器型号
- [ ] 底盘是不是正方形。不是的话固件里的 `L` 要改成实测的 `lx + ly`

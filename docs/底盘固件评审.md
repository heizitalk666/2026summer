## 0　先说这份固件实际上是什么

读完 `main.c` / `can_motor.c` 之后，几条与我们方案直接冲突的事实：

| 事实 | 依据 | 对我们的影响 |
|---|---|---|
| **完全没有 UART / 串口指令通路** | `Source/User/` 下 `grep USART\|UART` 零命中 | `docs/底盘串口协议.md` 不是"待硬件组确认"，是**待我们自己在这块 APM32 上实现** |
| 唯一控制入口是 **PS2 无线手柄** | `main.c` 主循环只读 `PS2_*` | 现在这台车没有任何办法被程序控制 |
| 底层只有 **(vx, vy, ω) 速度级接口** | `calculateWheelSpeeds(vx, vy, omega, ...)` → 四个轮子 rpm 走 CAN | ICD §4.1 的待决事项就此落地：**适配层必须写在 APM32 上，不能放到 RK3576** |
| 麦克纳姆轮，**可以横移** | `vy` 项存在且符号按 X 型排布 | 靠近柜面不必转身，对复核是好事 |
| 最高车速 **0.1 × (gear+1) = 0.1 / 0.2 / 0.3 m/s** | `MAX_SPD 0.1f`，`gear` 0–2 | 我们配置里的 0.5 m/s 不成立，**且 200 m 路线在 600 s 内跑不完**（见 §3） |
| 电机 CAN 回报 **rpm 与 position** | `CAN1_RX0_ISR` 收 0x97–0x9A → `g_MotorFbk[]` | 轮式里程计可做，定位不必等激光雷达 |
| PS2 掉线约 250 ms 后停车 | `count_timeout >= 4`，主循环 50 ms | 已有 deadman，与协议里的保活是同一类东西 |

底盘参数（`can_motor.c` 第 230–234 行）：轮径 0.2054 m（R = 0.1027 m）、对角轮距 0.5165 m。

## 1　F1　旋转项漏除轮半径　**严重**

`can_motor.c` `calculateWheelSpeeds()`：

```c
float omega_vx = vx / WHEEL_RADIUS;      // 单位 (m/s)/(m) = rad/s
float omega_vy = vy / WHEEL_RADIUS;      // rad/s

wheelSpeeds[0] = omega_vx + omega_vy + omega * L;   // ← omega*L 的单位是 m/s
```

**三项相加，但第三项和前两项不是同一个量纲。**麦轮逆运动学是

```
ω_wheel = ( vx ∓ vy ∓ (lx+ly)·ω ) / R
```

除以 R 是**整体**的，旋转项也要除。这不是取近似或换约定的问题，是加法两边单位不一致，属于确定性错误。

**后果**（实测算出来的数）：

| | 代码给出 | 正确值 | 差 |
|---|---|---|---|
| ω = 3.14 rad/s 时的轮角速度贡献 | 1.147 rad/s = **10.95 rpm** | 11.166 rad/s = **106.63 rpm** | **偏小 1/R = 9.74 倍** |
| 满打方向摇杆时的实际自转速度 | **18.5 °/s** | 180 °/s | — |

手感上就是"方向摇杆几乎推不动车头"。平移正常、旋转特别迟钝，正是这个 bug 的典型症状。

**改法**（一行）：

```c
    wheelSpeeds[0] = omega_vx + omega_vy + omega * L / WHEEL_RADIUS;
    wheelSpeeds[1] = omega_vx - omega_vy + omega * L / WHEEL_RADIUS;
    wheelSpeeds[2] = omega_vx + omega_vy - omega * L / WHEEL_RADIUS;
    wheelSpeeds[3] = omega_vx - omega_vy - omega * L / WHEEL_RADIUS;
```

**改完先在架空状态下试**，四个轮子都离地。旋转权限一下子变成原来的 9.7 倍，落地直接满打会甩。

> **附带一条：`L` 的注释是错的。**写的是「中心点到轮子的距离」，但值 `WHEEL_DISTANCE/√2 = 0.3652 m` 是 **lx + ly**；中心到轮子的距离是 `WHEEL_DISTANCE/2 = 0.2582 m`。数值本身对（对**方形**底盘成立），错的是注释——将来有人照着注释"修正"就会把它改坏。若底盘不是正方形，请分别量出前后轮距的一半 lx 与左右轮距的一半 ly，直接用 `lx + ly`。

## 2　F2　`if(flag)` 是死代码，而且一旦被"修好"就是安全陷阱　**严重**

`main.c`：

```c
uint8_t flag = 0;                       // 第 61 行：只在这里赋过值
...
if(flag)                                // 第 104 行
{
    flag = 0;
    calculateWheelSpeeds(vx, vy, omega, wheel_spd_f);
    ...
    can_motor_1_4_set_value(wheel_rpm);
}
```

全工程 `grep -n "\bflag\b"` 只有三处：定义、判断、清零。**没有任何地方把它置 1**，所以这段从来没执行过。看得出原意是"定时器中断里置位，主循环按固定周期重发速度"——一个标准的定速控制环，只是那个定时器没写。

危险在后面：这段代码**不检查 `start`，也不检查 PS2 是否还在**。谁要是哪天觉得"这里少了个定时器"顺手补上，车就会：

- `start == 0`（操作员没按启动）时照样按上一次的 `vx/vy/omega` 跑起来
- PS2 手柄掉线、deadman 已经把轮子清零之后，**下一个定时周期又把速度加回去**

`vx / vy / omega` 是全局变量，只在 `if(start)` 里被赋值，停车时**从不清零**——所以"上一次的速度"会一直留在那里。

**改法，二选一：**

```c
/* 方案甲：确认不需要定速环，直接删掉整个 if(flag) 块和 flag 变量 */

/* 方案乙：要保留定速环，就把安全条件补齐 */
if(flag)
{
    flag = 0;
    if(!start)                      /* 没启动就不许动 */
    {
        rt_memset(wheel_rpm, 0, sizeof(wheel_rpm));
        can_motor_1_4_set_value(wheel_rpm);
    }
    else { ...原逻辑... }
}
```

并且在每个停车分支里把 `vx = vy = omega = 0;` 一起清掉。**推荐方案甲**——现在的控制已经跟着 PS2 的 50 ms 节拍走了，不需要第二个环。

## 3　F3　PS2 掉线计数器不是"连续"计数　**中**

```c
if(Data[2] == 0x5A) { ...正常处理... }      /* ← 这里没有 count_timeout = 0; */
else
{
    if(count_timeout >= 4) { count_timeout = 0; start = 0; ...停车... }
    else count_timeout ++;
}
```

`count_timeout` 在正常分支里**从不清零**，所以它数的是"开机以来累计的坏包数"，不是"连续丢了几包"。实际行为变成：链路上零星的坏包攒够 5 个就停一次车，然后计数清零重新攒。

deadman 的语义应当是**连续**丢包才判定掉线。改法一行：

```c
if(Data[2] == 0x5A)
{
    count_timeout = 0;              /* ← 加这一行 */
    ...
}
```

## 4　F4　摇杆限幅写反　**低（当前不可达，但是个雷）**

```c
if(tmpx > 100)  tmpx = 100;
if(tmpx < -100) tmpx -= 100;        /* ← 应该是 tmpx = -100 */
```

`tmpy` / `tmpz` 三处一模一样。`-=` 会让本来就越界的负值**更负**，和限幅的意图正好相反。

当前不可达：`PS2_LY` 是 `uint8_t`，最大 255，代入 `-(255-128-7)*100/(127-7)` 恰好等于 −100，`< -100` 永远不成立。**但只要有人调了 `PS_GEAR`，或者换成 12 位 ADC 的摇杆，这三行立刻发作。**顺手改掉。

## 5　F5–F8　其余几处，请对着电机驱动手册核

| 编号 | 位置 | 问题 |
|---|---|---|
| **F5** | `can_motor_1_4_set_enable()` | 与 `can_motor_1_4_set_mode()` **实现完全相同**（同为 stdID 0x105、同样的字节排布），像是复制粘贴后忘了改。两个不同的命令走同一帧、同一布局，至少有一个是错的 |
| **F6** | `can_motor_1_4_set_fbk()` | 尾 4 字节 `rt_memset(&TxMeg.data[4], 0x80, 4)`，而 `set_mode` / `set_enable` 填 0。不一致，需要对手册确认 0x80 是不是有意义的 |
| **F7** | `can_motor_set_spd_rpm()` | **死代码，且索引映射与 main 相互矛盾**。它做 `tmp[MOTOR1_BUFFER_INDEX=3] = rpm[0]` 这样的重排，而 `main.c` 是直接 `can_motor_1_4_set_value(wheel_rpm)` 不重排。两套顺序并存，必有一套是错的。要么删掉，要么让 main 统一走它 |
| **F8** | `CAN1_RX0_ISR` ↔ 主循环 | `g_MotorFbk[]` 由中断整块 `rt_memcpy` 8 字节写入，主循环无临界区读取，可能读到撕裂的值。现在 main 根本没读它所以没事——**但我们要做轮式里程计的话，第一件事就是读它**。届时需要双缓冲，或读之前短暂关 CAN RX 中断 |

## 6　这台车能不能满足任务书的指标

不能，而且差得不是一点。把实测参数代进复核预算公式
`N_max = ⌊(T_max − L_route/v) / T_r⌋`（T_max = 600 s，T_r = 9.2 s）：

| 车速 | 200 m 路线 | 120 m | 60 m |
|---|---|---|---|
| 0.50 m/s（我们原配置） | 巡航 400 s → **N_max = 21** | 240 s → 39 | 120 s → 52 |
| **0.30 m/s（本车最高档）** | 巡航 **667 s → N_max = 0** | 400 s → 21 | 200 s → 43 |
| 0.20 m/s（中档） | 1000 s → 0 | **600 s → 0** | 300 s → 32 |
| 0.10 m/s（低档） | 2000 s → 0 | 1200 s → 0 | 600 s → 0 |

**这台车用最高档跑 200 m，光巡航就要 667 s，已经超过 600 s 的单轮上限，一次复核都排不下。**

三条出路，D3 评审上挑一条：

1. **缩短路线到 60 m**（0.3 m/s 下 N_max = 43，余量充足）。最省事，也最符合"实训场地本来就不大"的现实
2. **放宽 T_max**。把单轮时限从 600 s 提到 1200 s，200 m 在 0.3 m/s 下 N_max = 57
3. **提高 MAX_SPD**。固件里改一个宏就行，但要先确认电机与地面的实际能力——限幅 210 rpm 对应轮周速 2.26 m/s，电机侧远没到头，**瓶颈是 `MAX_SPD 0.1f` 这个人为设的值**，不是硬件

我们代码这一侧已经按 0.25 m/s 与 60 m 重新配好了（见 `configs/system.yaml` 的 `mission.budget`），`validate.py` 现在会在 `N_max = 0` 时直接判失败，不会让这个矛盾悄悄溜过去。

## 7　串口指令通路要我们自己在 APM32 上实现

好消息是：**固件源码在我们手上**，所以适配层可以严格按 ICD §4.1 的要求落在底盘 MCU 上——RK3576 与底盘之间的链路上永远不会出现 vx / vy / ω 这类量。

要加的东西不多，主循环旁边起一个 UART 接收，把 `docs/底盘串口协议.md` 的六条任务级指令翻成本地的速度指令：

| 协议指令 | 在 APM32 上怎么实现 |
|---|---|
| `PAU` 请求停车 | 目标速度置 0，按固定减速度斜坡到 0；停稳后状态由 `STOPPING` 转 `STOPPED` |
| `RES` 恢复巡检 | 沿标定路线继续。**路线点存在 APM32 的 flash 里**，不由上位机下发 |
| `CRP` 微动 `distance_mm` | 用 `g_MotorFbk[].position` 做闭环，走够距离自己停。上限在固件里再限一道 500 mm |
| `GTO` 去某个巡检位 | 同上，靠轮式里程计推算；到位公差由参数给 |
| `QRY` / `PNG` | 回状态帧 / 喂保活。**保活超时自行减速停车**——和现在的 PS2 deadman 是同一套机制，复用即可 |
| `STA` 状态上报 | 20 Hz。`state` 必须区分 `STOPPING` 与 `STOPPED`，上位机的 HALT_REQ 等的是后者 |
| `SAF` 安全事件 | 现有的 PS2 掉线停车、以及将来加的碰撞/急停，都从这里上报，**不等周期立刻发** |

**PS2 手柄要保留**，并且优先级高于串口——现场调试和出事时人工接管都靠它。建议在固件里加一个"遥控/自动"模式位，手柄任意输入即抢占为遥控模式。

上位机那一侧已经写好了（`patrol/drivers/real/chassis_serial.py`），还有一个说同一套协议的假小车（`patrol/tools/fakecar.py`），APM32 这边写完可以直接对拷验证。

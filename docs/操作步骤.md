# 操作步骤

从零到跑通全链路。所有命令在仓库根目录执行。

## 0　装环境

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt                       # 约 80 MB
```

只需要 Python 3.10+。**不需要 GPU，不需要板子，不需要小车。**

若终端没有显示器（服务器、WSL 无 X），把 `opencv-python` 换成
`opencv-python-headless`；除了预览窗口，其余功能不受影响。

## 1　先跑一致性校验

```bash
python -m patrol.tools.validate
```

期望输出末行：

```
PASS  Schema 5 份、正例 6 条、反例 9 条、内嵌副本一致、算例与预算全部自洽、网关常量与 Schema 同步（共 50 项）
```

这一步不过就别往下走：说明接口定义与代码已经对不上了。**建议接进 CI**，
每次改 Schema 自动跑一遍。

## 2　看一眼虚拟配电室

```bash
python -m patrol.tools.viewer --demo-zoom --out out/     # 出一张变焦对比图
python -m patrol.tools.viewer                            # 有显示器：开窗口，键盘控云台
python -m patrol.tools.viewer --headless --out out/      # 无显示器：存帧
```

`out/zoom_compare.png` 是全项目最直观的一幕：同一块压力表，巡航态 49.8 px
（读不出指针），3× 变焦后 149.5 px（刻度清晰可读）。

窗口模式键位：`A/D` 左右转、`W/S` 俯仰、`Q/E` 变焦、`空格` 停/走、
`H` 云台归位、`R` 注入安全事件、`L` 注入定位失锁、`ESC` 退出。

## 3　跑测试

```bash
pytest -q                    # 全部
pytest tests/test_reading_accuracy.py -v      # 只看精度指标
pytest tests/test_servo.py -v                 # 只看控制指标
```

## 4　标定

```bash
python -m patrol.tools.calibrate --out out/calib
```

产出 `out/calib/` 下的 `calibration.md`（标定报告）、`calibration_curve.png`
（标定曲线）、`calibration.csv`（五点各 10 次的原始数据）、`pixel_density.csv`
（像素密度标定）。这些是方案书 §11.1 交付物清单里的「标定记录」。

真机上加 `--interactive`，程序会提示你把表针调到某个位置再回车。

## 5　PID 整定与阶跃响应

```bash
python -m patrol.tools.tune_pid --out out/pid --tune --compare-gain-schedule
```

产出 `out/pid/step_response.png`（阶跃响应曲线）、`step_response.csv`、
`pid_report.json`。这些是「PID 整定记录、阶跃响应曲线」。

`--compare-gain-schedule` 会额外跑一条关掉增益调度的曲线，用来演示
方案书 §6.3.2 说的那件事：不做调度时变焦到 3× 会大幅超调。

## 6　跑全系统

```bash
python -m patrol.tools.run_all                   # 跑到 Ctrl-C
python -m patrol.tools.run_all --seconds 120     # 跑 120 秒后自动收工并出报告
python -m patrol.tools.run_all --no-cloud        # 只跑边缘端
```

会起五个进程：`gateway` → `perception` → `mission` → `uploader` → `cloud`。
跑完打印一轮巡检小结（证据包数、复核成功率、按结论分组的 Δconf）。

浏览器打开 <http://127.0.0.1:8000/> 看台账：

- **巡检台账** 所有证据包，点「详情」看图像、状态机耗时、增益指标
- **人工复核** 待复核队列（L3 未知异常与 INCONCLUSIVE 恒需人工确认）
- **复核增益** 三项答辩指标，按结论分组
- **模型版本** 登记哪一版模型产生了哪些结论

## 7　演示三条安全路径

方案书 §7.4 说安全设计的说服力不在于声明，而在于能当场演示。三条都能演示：

```bash
# 一、越界指令被拒并留下审计记录
pytest tests/test_gateway.py::test_100_out_of_range_commands_all_blocked -v
cat logs/gateway-audit.jsonl | head -3

# 二、杀掉 AI 进程后车自行恢复巡航
python -m patrol.tools.run_all &
pkill -f patrol.mission.node          # 心跳停了
grep 看门狗 logs/*gateway*.jsonl      # 1.5 s 后网关下发 RESUME

# 三、注入安全事件后复核立即中止
pytest tests/test_fsm.py::test_safety_event_aborts_within_200ms -v
```

第二条也可以在 viewer 窗口里按 `R` 手工注入安全事件观察。

## 8　切换配置开关

差异清单 A1–A4 四条争议都是配置开关，改 `configs/system.yaml` 一行即可：

| 开关 | 取值 | 说明 |
|---|---|---|
| `mission.servo.mode` | `pid` / `open_loop` | PID 速率闭环 vs ICD v1.0 的开环指向 |
| `mission.servo.gain_schedule` | `true` / `false` | 关掉可现场演示变焦后的振荡 |
| `mission.capture.mode` | `conditional` / `burst` / `multiview` | 三种采集策略 |
| `perception.detector` | `synthetic` / `yolo` | 权重就位后切到 yolo |
| `driver_mode` | `stub` / `real` | 硬件到位后切到 real |

## 9　硬件到位后

```bash
# 先用假小车验证串口链路（不需要真车）
python -m patrol.tools.fakecar --pty
# 把打印出来的设备路径填进 configs/system.yaml 的 real.serial.port
# driver_mode 改成 real，然后照常
python -m patrol.tools.run_all
```

协议见 `docs/底盘串口协议.md`，其中第 5 节是交给硬件组的对接清单。

## 10　训模型

代码先行、模型后训。等公开数据集与权重就位：

```bash
pip install -r requirements-yolo.txt      # 约 2.5 GB
python -m training.prepare_dataset        # 下载并整理公开数据集
python -m training.train_detector --stage cruise
python -m training.train_detector --stage verify
# 然后把 configs/system.yaml 的 perception.detector 改成 yolo
```

见 `training/README.md`。

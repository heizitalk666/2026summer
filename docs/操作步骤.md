# 操作步骤

从零到跑通全链路。所有命令在仓库根目录执行。

## 0　装环境

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt                       # 约 80 MB
```

只需要 Python 3.10+。**不需要 GPU，不需要板子，不需要小车。**

若终端没有显示器（服务器、WSL 无 X），把 `opencv-python` 换成
`opencv-python-headless`；除了预览窗口，其余功能不受影响。

## 1　先跑一致性校验

```bash
python -m patrol.tools.validate
```

期望输出末行：

```
PASS  Schema 5 份、正例 6 条、反例 11 条、内嵌副本一致、算例与预算全部自洽、网关常量与 Schema 同步（共 57 项）
```

这一步不过就别往下走：说明接口定义与代码已经对不上了。**建议接进 CI**，
每次改 Schema 自动跑一遍。

## 2　看一眼虚拟配电室

```bash
python -m patrol.tools.viewer --demo-zoom --out out/     # 出一张变焦对比图
python -m patrol.tools.viewer                            # 有显示器：开窗口，键盘控云台
python -m patrol.tools.viewer --headless --out out/      # 无显示器：存帧
```

`out/zoom_compare.png` 是全项目最直观的一幕：同一块压力表，巡航态 49.8 px
（读不出指针），3× 变焦后 149.5 px（刻度清晰可读）。

窗口模式键位：`A/D` 左右转、`W/S` 俯仰、`Q/E` 变焦、`空格` 停/走、
`H` 云台归位、`R` 注入安全事件、`L` 注入定位失锁、`ESC` 退出。

## 3　跑测试

```bash
pytest -q                    # 全部
pytest tests/test_reading_accuracy.py -v      # 只看精度指标
pytest tests/test_servo.py -v                 # 只看控制指标
```

## 4　标定

```bash
python -m patrol.tools.calibrate --out out/calib
```

产出 `out/calib/` 下的 `calibration.md`（标定报告）、`calibration_curve.png`
（标定曲线）、`calibration.csv`（五点各 10 次的原始数据）、`pixel_density.csv`
（像素密度标定）。这些是方案书 §11.1 交付物清单里的「标定记录」。

**已经跑过一份归档在 [`deliverables/组长-系统/artifacts/calib/`](../deliverables/组长-系统/artifacts/calib/)**，
连同 43 次独立标定的指标分布。**单跑一次的数不要直接拿去报**——重复性在
0.19–0.36 % FS 之间跳，报哪个都像在挑数，要报就报分布的中位与超限比例。

真机上加 `--interactive`，程序会提示你把表针调到某个位置再回车。

## 5　PID 整定与阶跃响应

```bash
python -m patrol.tools.tune_pid --out out/pid --tune --compare-gain-schedule
```

产出 `out/pid/step_response.png`（阶跃响应曲线）、`step_response.csv`、
`pid_report.json`。这些是「PID 整定记录、阶跃响应曲线」，
**已归档一份在 [`deliverables/组长-系统/artifacts/pid/`](../deliverables/组长-系统/artifacts/pid/)**
（PPT 引用的就是那一份，改了记得两边一起换）。

`--compare-gain-schedule` 会额外跑一条关掉增益调度的曲线，用来演示
方案书 §6.3.2 说的那件事：不做调度时变焦到 3× 会大幅超调。

## 6　跑全系统

```bash
python -m patrol.tools.run_all                   # 跑到 Ctrl-C
python -m patrol.tools.run_all --seconds 120     # 跑 120 秒后自动收工并出报告
python -m patrol.tools.run_all --no-cloud        # 只跑边缘端
```

会起五个进程：`gateway` → `perception` → `mission` → `uploader` → `cloud`。
跑完打印一轮巡检小结（证据包数、复核成功率、按结论分组的 Δconf）。

浏览器打开 <http://127.0.0.1:8000/> 看台账：

- **巡检台账** 所有证据包，点「详情」看图像、状态机耗时、增益指标
- **人工复核** 待复核队列（L3 未知异常与 INCONCLUSIVE 恒需人工确认）
- **复核增益** 三项答辩指标，按结论分组
- **模型版本** 登记哪一版模型产生了哪些结论

## 6.5　把指令直接显示出来（三个显示面）

没有硬件时，这三个面就是"车"和"云台"唯一看得见的样子。数据源只有一个
（网关审计日志 + IF-3），所以三处说的话一定一致。

```bash
# 最省事：系统和指令流水一起起，并推给云端网页
python -m patrol.tools.run_all --console

# 或者分开起——控制台先开也没关系，文件还没生成时它会等着
python -m patrol.tools.console                        # 终端实时流
python -m patrol.tools.console --from-start           # 从头回放这一轮
python -m patrol.tools.console --heartbeat            # 连 5 Hz 心跳一起看
python -m patrol.tools.console --push http://127.0.0.1:8000   # 同时推给网页

# 预览窗口：跟着正在跑的系统看，画面上叠加指令
python -m patrol.tools.viewer --live
python -m patrol.tools.viewer --live --headless --out out/    # 无显示器时存帧
```

**终端**长这样，一次完整复核的节奏能直接读出来：

```
[t=   80.7s] → 小车   ✓ 暂停 VERIFY_REQUEST                       1.5 ms
[t=   83.3s] → 云台   ✓ 转到 pan=+110.0° tilt=+2.7° zoom=1.00×    1.6 ms
[t=   84.1s] → 云台   ✓ 转速 pan=+3.6°/s tilt=+0.3°/s             0.5 ms
[t=   84.7s] → 云台   ✓ 转到 pan=+111.1° tilt=+2.7° zoom=2.59×    0.9 ms
[t=   86.9s] → 小车   ✓ 恢复巡航                                    0.9 ms
车 (14.30, -3.18) yaw=+0° STOPPED 0.00 m/s WP-05 │ 云台 zoom=2.59× 视场 25.2°
```

被拒的指令标红，并打出六项检查里是哪一项没过——**这是三层安全边界唯一
可观测的地方**（ICD §4.6 要求逐项上报正是为了这个）。5 Hz 心跳默认折叠，
一轮三千多条会把真正的指令淹掉；但**被拒的心跳照常显示**，那说明看门狗
出了问题。

**网页「实时」页**（<http://127.0.0.1:8000/>）左边是同一份指令流水，右边是
配电室俯视图：过道折线、航点、柜面目标、车的位姿箭头，以及随变焦收窄的
**云台视场扇形**——扇形一收紧就是"正在放大细看"。

**预览窗口** `--live` 不自己控云台，而是订阅 IF-3 拿真实位姿与云台角，
经 `ICamera.observe_state` 回灌给相机桩（和感知节点走的是同一条通路，见
`docs/架构说明.md`）。于是"指令下去了、云台转了、画面跟着变了"能在同一块
屏幕上对上号。

## 7　演示三条安全路径

方案书 §7.4 说安全设计的说服力不在于声明，而在于能当场演示。三条都能演示：

```bash
# 一、越界指令被拒并留下审计记录
pytest tests/test_gateway.py::test_100_out_of_range_commands_all_blocked -v
cat logs/gateway-audit.jsonl | head -3

# 二、杀掉 AI 进程后车自行恢复巡航
python -m patrol.tools.run_all &
pkill -f patrol.mission.node          # 心跳停了
grep 看门狗 logs/*gateway*.jsonl      # 1.5 s 后网关下发 RESUME

# 三、注入安全事件后复核立即中止
pytest tests/test_fsm.py::test_safety_event_aborts_within_200ms -v
```

第二条也可以在 viewer 窗口里按 `R` 手工注入安全事件观察。

## 8　切换配置开关

差异清单 A1–A4 四条争议都是配置开关，改 `configs/system.yaml` 一行即可：

| 开关 | 取值 | 说明 |
|---|---|---|
| `mission.servo.mode` | `pid` / `open_loop` | PID 速率闭环 vs ICD v1.0 的开环指向 |
| `mission.servo.gain_schedule` | `true` / `false` | 关掉可现场演示变焦后的振荡 |
| `mission.capture.mode` | `conditional` / `burst` / `multiview` | **预留未生效**：三种采集策略都还没有代码路径，改这个值当前不影响行为 |
| `perception.detector` | `synthetic` / `yolo` | 权重就位后切到 yolo |
| `driver_mode` | `stub` / `real` | 硬件到位后切到 real |

## 9　硬件到位后

```bash
# 先用假小车验证串口链路（不需要真车）
python -m patrol.tools.fakecar --pty
#   → 打印出 /dev/pts/N 和本次的随机种子
# 把这个设备路径填进 configs/real.yaml 的 real.serial.chassis.port，
# 再把 configs/system.yaml 的 driver_mode 改成 real，然后照常
python -m patrol.tools.run_all
```

真机参数全部集中在 `configs/real.yaml`（端口名、波特率、云台限位、相机
设备号）。**硬件到位后要改的就是那一个文件**，上位机代码一行不用动——
这正是 ICD §8.7 那个"唯一分支点"设计要换来的东西。

假小车复用了 `chassis_stub` 的故障注入：停车延迟 1.5–2.5 s、2 % ACK 丢包、
随机障碍物与急停都会原样出现在串口链路上。所以偶尔看到一条 `PAUSE` 发出去
车没停是**正常的**，那是按设计丢的包，上层靠超时重发。要复现某次现象就用
`--seed` 把种子固定下来。

不接假小车也能验协议：

```bash
pytest tests/test_serial_protocol.py -v    # 编解码 + 内存回环 + 真伪终端往返
```

协议见 `docs/底盘串口协议.md`，其中第 5 节是交给硬件组的对接清单。

## 10　训模型

代码先行、模型后训。等公开数据集与权重就位：

```bash
pip install -r requirements-yolo.txt      # 约 2.5 GB
python -m training.prepare_dataset        # 下载并整理公开数据集
python -m training.train_detector --stage cruise
python -m training.train_detector --stage verify
# 然后把 configs/system.yaml 的 perception.detector 改成 yolo
```

L3 未知异常是非监督的，**不需要缺陷标注**，跑过一轮就能从证据包里攒样本：

```bash
python -m training.train_anomaly --from-evidence evidence --backend statistical
# 产出 training/runs/anomaly/baseline.json，填进 perception.l3.weights
# 省掉冷启动那 30 个样本的预热期；不填也照常跑
```

板子到位后再量化上 NPU：

```bash
python -m training.export_rknn --weights training/runs/cruise/weights/best.pt
# 量化校准集直接从 evidence/ 里取 cruise_raw.jpg —— 必须是本场景的图，
# 拿 COCO 之类的通用图校准，INT8 掉点会明显大于预期
```

见 `training/README.md`。

## 11　多模型识别：造数据、训练、横向对比

思路见 `docs/多模型协同.md`。这里只列命令。

```bash
# 1. 从渲染器生成带标注的合成数据集（检测框 / 分割掩膜 / OCR / L3 正常集）
python -m training.gen_synthetic --n 400 --out training/datasets/synth
```

跑完看它打印的**自检报告**，两件事必须对：

- 像素密度分布要**同时覆盖判据线两侧**。只覆盖一侧说明采样参数与场景距离
  不匹配，训出来的模型学不到"密度不够时别硬猜"
- `check/` 里的核对图**务必人眼抽查几张**。掩膜错位、类别号错位在任何统计
  量上都看不出来，只有把标签画回图上才一眼看得见

```bash
# 2. 训分割（几秒钟。这是逻辑回归基线，不是 U-Net——见文档第五节）
python -m training.train_segmenter --data training/datasets/synth

# 3. 横向对比，用数据决定每一路开不开
python -m patrol.tools.bench_models
python -m patrol.tools.bench_models --seg-weights training/runs/seg/pixel.npz

# 4. 真要上 U-Net / YOLO：训完导 ONNX，导出后会当场跑冒烟推理
python -m training.export_onnx --detector training/runs/cruise/weights/best.pt
python -m training.export_onnx --segmenter my_unet.pt --seg-arch mypkg.UNet
```

启用某一路，只改配置，`patrol/` 下一行不动：

```yaml
perception:
  detector: yolo              # synthetic | yolo
  segmenter: {backend: npz}   # builtin | npz | onnx
  ocr: {backend: rapid}       # rapid | off
  l3: {model: efficientad_s}
```

**OCR 这一路装上就能用**（`rapidocr-onnxruntime` 15 MB 自带 ONNX 权重、
完全离线、不依赖 torch），不需要训练。装不上时自动降级为 off，链路不断。

一轮跑完之后，四路模型的逐条判断在这里：

```bash
cat evidence/*/*/fusion.json      # 融合的完整证据链与理由
cat evidence/*/*/meta.jsonl       # IF-1/IF-3 原始报文，可逐帧重放
```

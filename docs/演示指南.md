# 演示指南

**没有硬件时怎么把这套系统演给人看。**所有命令在仓库根目录执行。

演示的重心不是"识别有多准"——那一块目前是桩，见 `后续计划与分工.md`。重心是
**边缘端能不能自己做决定、做完之后能不能拿出证据**。这一条不依赖任何权重，
而且每一步都能当场跑。

---

## 0　开窗与投影

三个系统上都是同一条命令，不用加任何前缀：

```bash
python -m patrol.tools.viewer ...
```

`viewer.py` 的 `_no_display()` 按平台判断能不能开窗：Windows 与 macOS 上
`cv2.imshow` 不依赖 `DISPLAY`，直接开；只有 Linux 才看这个环境变量。
（旧文档里那个 `DISPLAY=win` 前缀已经不需要了，看到就忽略。）
真要存帧不开窗，用 `--headless --out out/`。

窗口默认缩到 1280×720 显示，而画面是按 1920×1080 渲染的，缩放会让左上角
叠加层的字发虚。答辩投影时用 `--window native` 按原分辨率显示，字最清楚；
屏幕放不下就折中一个尺寸，比如 `--window 1600x900`。

## 1　主线：三块屏幕，一条时间线

**这是演示的主体，8–10 分钟。**三块屏幕要同时开着，因为它们各自只回答一个
问题，合起来才是完整的因果链：

| 屏幕 | 回答的问题 |
|---|---|
| 指令流水 | 边缘**下发了什么** |
| 3D 车载视角 | 它**看见了什么** |
| 第三人称 | 它**在看哪儿** |
| 云端台账 | 结论**存下来了没有** |

### 起系统

```bash
python -m patrol.tools.run_all --seconds 600 --console
```

`--console` 会同时起指令流水控制台，并把它推给云端网页的「实时」页。
不加这个参数，网页上的指令流水是空的。

### 再开两个窗口

```bash
python -m patrol.tools.viewer --live          # 跟着真实系统跑
python -m patrol.tools.viewer --thirdperson   # 车载 + 第三人称并排
```

`--live` 那个是**只读**的：它订阅 IF-3 拿真实位姿与云台角，回灌给相机桩，
所以画面和真车看到的一致。`--thirdperson` 是自己驱动的一台仿真车，可键盘操作。

### 浏览器

打开 <http://127.0.0.1:8000>，五个页签：巡检台账 / 人工复核 / 复核增益 /
模型版本 / 实时。

## 2　演示时说什么

### 指令流水（最要紧的一块屏）

一次完整复核在流水里长这样，六行就是整个立论：

```
OK PTZ_RATE   转速 pan=-2.0°/s              伺服闭环，速率在收敛
OK PTZ_RATE   转速 pan=-1.7°/s
OK PTZ_RATE   转速 pan=-1.6°/s
OK PTZ_SET    转到 pan=+68.8° zoom=2.60×    对准后变焦，倍率是按需算的
OK PTZ_SET    转到 pan=+90.0° zoom=1.00×    复核完毕，云台归位
OK RESUME     恢复巡航
```

**要说的点**：变焦倍率 2.60× 不是写死的常数，是
`z = clip(p_target/p_before, 1, max_zoom)` 按当前像素密度算出来的——目标离得
近就少放大一点。每条指令都带六项校验的逐项裁决，网关处理耗时中位 524 μs、
p95 1113 μs（见 `logs/gateway-audit.jsonl`）。

### 3D 车载视角

橙框 = 像素密度不达标、需复核；绿框 = 达标。巡航时看到的表大多是橙的
（10 m 外只有 20–30 px），这正是"必须停车变焦"的理由。

### 第三人称（键盘可操作）

点一下窗口获得焦点：

```
A / D   左右转云台          转的时候看视锥跟着扫
W / S   俯仰
Q / E   变焦               ← 最值得试的一个
空格    暂停 / 恢复行驶
H       云台归位
R       强制安全事件        触发安全层，看指令被拒
L       强制定位失锁
ESC     退出
```

**按住 E 变焦到 3×**：右边那个扇形从 **60° 收到 21.8°** 并套住一块表。
这就是"停车 → 对准 → 变焦 → 再看一眼"在三维里的样子。

顺带一个可以主动讲的点：3× 时视场是 21.79° 而**不是** 60/3 = 20°——视场角与
倍率成反正切、不成反比。按 20° 算像素密度会系统性偏大 9 %，正好把"够不够
120 px"的判据推到错误的一侧。窗口 HUD 上的 `hfov` 字段现场就能验。

### 云端台账

- **「实时」页**：上方是「发现即报」告警表，下方指令流水，右侧俯视图（车会动）
- **「巡检台账」**：点开任一条看证据包——cruise 一张 + verify 三张 + ROI，
  以及 Δconf、密度比、状态机各段耗时
- **「复核增益」**：按结论分组的统计

## 3　支线：四条，每条 1–2 分钟

### 3.1　发现即报（边缘自治的时延证据）

系统跑起来后，「实时」页顶部的告警表会先于证据包出现。

**实测：告警比证据包中位提前 17.4 秒**（最小 12.2 s，最大 18.4 s，6 组配对）。
原因是证据包要等整个复核周期走完——FSM 预算加总 9.2 s、最坏超时 22 s——而告警
在 suspect 一确认就发。

两条通路的保证级别**故意不同**：告警秒级、轻量、允许丢；证据包保证不丢，走
断点续传。丢一条告警不丢信息，因为证据包随后会带着完整数据到达。

### 3.2　断网自治

```bash
python -m patrol.tools.run_all --seconds 75 --no-cloud --quiet
find evidence -name upload_state.json | head    # 看 rounds 在涨、failed 为空
```

云端**完全不存在**，边缘照常发现、判断、定级、打包落盘，并诚实地把数据标成
"还没传上去"一直留着。实测 75 s 产出 4 份证据包，每份 10 个文件，`rounds`
涨到 8–14（一直在退避重试），`failed` 为空，`uploaded` 为空。

**要说的点**：`rounds` 在涨这件事比"产出了 4 份包"更有说服力——它证明
uploader 在断网期间**一直在正常轮转**，而不是卡在重试上不再打包新证据。

### 3.3　真串口协议栈（没有板子时最有力的一张牌）

```bash
# 终端 A：假小车。Windows 用 --tcp，POSIX 可用 --pty
python -m patrol.tools.fakecar --tcp
# 把它打印的 tcp://127.0.0.1:5760 填进 configs/real.yaml 的
# real.serial.chassis.port，再把 configs/system.yaml 的 driver_mode 改成 real

# 终端 B：正常起系统
python -m patrol.tools.run_all --seconds 300 --console
```

**这一层证明的不是"仿真跑通了"，是"真机代码路径跑通了，只差把对面换成真设备"。**
走的是 `docs/底盘串口协议.md` 那套真协议——帧编解码、CRC、超时、重传全是真的，
而且车体行为复用 `ChassisStub`，所以 2 % ACK 丢包、1.5–2.5 s 停车延迟原样出现
在串口链路上。

被问到时要主动说清楚**它不能替代什么**：TCP 环回没有波特率、没有线路噪声、
没有帧错误，还保证有序不丢。所以它证明协议栈与时序逻辑正确，**不证明物理层**。

### 3.4　安全边界

```bash
pytest tests/test_gateway.py -k out_of_range -v      # 越界指令被拒，留审计记录
pytest tests/test_fsm.py -k safety -v                # 安全事件 200 ms 内中止复核
python -m patrol.tools.tune_pid --out out/pid --compare-gain-schedule
```

第三条是反证：关掉增益调度后 3× 变焦下超调从 0.9 % 变成 47.6 %，两张图对比。

也可以在第三人称窗口里按 **R** 现场触发安全事件，然后在指令流水里看运动指令
被 `SAFETY_OVERRIDE` 拒掉，而云台指令照常放行（复核中止时恰恰需要把云台归位）。

## 4　给 PPT 出静态图

不需要起系统，单独跑就出图：

```bash
# 立论那一幕：同一块表，z=1 与 z=3（车载视角）
python -m patrol.tools.viewer --demo-zoom --out out/
#   → out/zoom_compare.png   实测 50.0 / 150.0 px，公式 49.8 / 149.5 px

# 同一件事的第三人称版：视锥从 60° 收到 21.8° 并落在表盘上
python -m patrol.tools.viewer --demo-thirdperson --out out/
#   → out/thirdperson_compare.png

# 阶跃响应曲线（方案书 §11.1 点名的交付物）
python -m patrol.tools.tune_pid --out out/pid
#   → out/pid/step_response.png / .csv / pid_report.json

# 沿巡检路线的连续帧，可拼成演示视频
python -m patrol.tools.viewer --headless --out out/frames --seconds 30 --fps 2
```

这两张图是一对：`zoom_compare` 说"表盘从 50 px 放大到 150 px"，
`thirdperson_compare` 说"视场从 60° 收到 21.8° 并且正好套住那块表"。
一个从车的眼睛里看，一个从旁边看着车。放一起，"停车→对准→变焦→再看一眼"
这句话不需要再解释。

## 5　演示前检查清单

```bash
python -m patrol.tools.validate     # 必须 57/57 全绿，不过就别演
python -m pytest -q                 # 505 条用例
```

再确认三件事：

1. **端口空闲**：8000（云端）与 `configs/system.yaml` 里 `bus.*` 那几个。
   上一轮没退干净会导致新的起不来。
2. **中文字体在**：`python -c "from patrol.tools.textdraw import cjk_available;
   print(cjk_available())"` 要打印 `True`，否则叠加层会退回英文缩写。
3. **可选依赖**：不装 `rapidocr-onnxruntime` 时 OCR 那一路自动降级为 off，
   链路不断但少一路证据。要演 OCR 互证就先 `pip install rapidocr-onnxruntime`
   （15 MB，自带权重，离线可跑）。

## 6　被问到时的两个诚实答法

**问：没有硬件，凭什么说这是边缘计算系统？**

边缘部署这一环**未验证，我们不声称**。能证明的是架构对部署是中立的：四进程
边界让感知崩溃不影响执行器、权重统一走 ONNX 这条 RKNN 工具链吃的格式、切真机
只改两处配置。板子到了接得上，这是可检查的；跑多快，现在没有数。

**问：这些数字在合成场景上测的，算不算数？**

分两类。**算数的**：像素密度和读数误差——渲染服从针孔投影，公式是投影的推论，
而且有三条防作弊测试盯着（误差必须随密度退化、换量程读数必须线性缩放、场景
先验不许泄漏真值）。**不算数的**：检测相关的一切，那一路目前是桩。真实表盘上
的误差大概率比合成场景差一个量级，这个 sim-to-real gap 本身就是值得讲的东西。
